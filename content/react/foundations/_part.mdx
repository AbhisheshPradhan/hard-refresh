Everything in this part exists to answer one question: how do you describe an interface so that it stays correct as the data behind it changes?

Written by hand, that job is endless. You add a listener, find the element, change its text, remember to also update the count in the header, remember to remove the row from the array, remember to disable the button while the request is in flight. Every piece of state has to be manually propagated to every place that displays it, and the bugs are always the same: two parts of the screen disagreeing about what is true.

React's answer is to invert it. You do not write the steps that change the screen. You write a function that says what the screen should look like for the current data, and React works out the steps.

Everything here is covered somewhere in the book. This page exists because when something is broken you know the symptom, not the topic.

## State is stale, or the screen disagrees with the data

| Symptom | Chapter |
|---|---|
| Read state on the line after setting it — that variable belongs to the current render | 4 |
| Mutated an object or array and passed the same reference to the setter | 4, 10 |
| Several updates that each read the old value; needed the functional form | 4 |
| A long-lived callback — interval, listener, subscription — captured an old render | 10 |
| State derived from props, initialised once and now diverged | 11, 14 |
| Two components each holding their own copy of server data | 13, 16 |

## An effect runs too often, or never stops

| Symptom | Chapter |
|---|---|
| Object, array or function in the dependency array — new identity every render | 11 |
| No dependency array at all, and the effect sets state | 11 |
| The effect sets state it also depends on | 11 |
| It should not be an effect: the value is derived, or belongs in a handler | 11 |
| Runs twice in development — missing cleanup, exposed by StrictMode | 10 |

## Too many re-renders, or the page feels slow

| Symptom | Chapter |
|---|---|
| State sits higher than the component that uses it | 14 |
| An expensive subtree is created inside the component whose state changes | 14 |
| One context carrying values with very different change frequencies | 14 |
| `memo` defeated by an inline object or arrow prop | 22 |
| A selector returning a new array or object on every call | 15 |
| Too many DOM nodes — the cost is layout and paint, not React | 23 |
| Slow to become interactive: bundle size, not rendering | 22 |
